## 结论与证据口径

当前最完整的是「装修获客 → 预约 → 后台分配员工 → 跟进/上门 → 完成预约 → 创建项目/报价 → 客户确认 → 完工或取消」。商品商城仍以原型为主。不能把已有数据库表、已定义 API、成功提示或列表里存在完成记录，直接当作整条业务实际验收通过。

- **真实读取已验证**：本次对本地运行中的 `http://localhost:3000/api` 发出请求，获得成功响应。
- **接口闭环已实现**：页面调用、后端业务逻辑和持久化实现均存在，相关测试通过；本次未新建业务数据逐步执行全部写入，因此不标为真机端到端验收通过。
- **部分接通**：某些步骤真实读写，仍存在流程缺口。
- **未接通**：静态数据、本地状态或提示消息，尚无对应业务请求。

本次用项目现有开发测试会话读取客户/员工数据，未修改鉴权逻辑，也未删除数据库中的任何记录。接口数据属于本地环境，不据此判断线上部署状态。

## 接下来的开发顺序

### 1. 收口装修主线，完成跨角色真实验收（P0）

先把已有能力验收稳定，避免重复开发已存在的预约、建项、报价接口。

- 员工预约状态筛选下沉到服务端，分页及状态计数使用相同条件；超过一页数据时不能漏单。
- 补齐建项返回预约详情、跨页面返回后的刷新；不应依靠本地缓存判断是否已建项。
- 统一业务错误处理：当前 request 对 HTTP 2xx 中 code=400 仍 resolve，部分调用方仅 await 就提示成功；应统一拒绝业务错误并检查所有写入口。
- 明确 BUDGET / CASE 是否允许取消并补齐；当前只有 PLAN 可取消，不应描述为全部预约均支持取消。
- 客户项目筛选补充已取消分组（当前 ALL 可看到取消项目，但没有单独筛选）；状态展示和取消详情一致。
- 方案预约补服务端重复提交约束；当前按钮防重复不能覆盖超时重试/重复请求。
- 明确分享客户归属规则，打通分享参数 → 预约来源记录 → 分配/归属；无有效分享来源时仍使用后台分配。

**验收**：BUDGET、PLAN、CASE 各一条，从客户提交、管理端分配、员工跟进上门到建项、改报价、客户确认、完成；另覆盖预约取消、项目取消、旧版本确认冲突、网络失败重试，双方刷新后数据一致。

### 2. 接通商城商品目录（P1，下一块主要开发）

复用现有 `/product-category`、`/product`、商品详情接口，让商品页、搜索页、详情页使用真实 ID、分类、关键词、上下架与库存。先明确商品规格是属性展示还是独立 SKU，当前页面的三种规格仅为静态选项。

**验收**：后台修改商品后前台读取一致；分类与搜索真实筛选；不同商品 ID 展示不同详情；下架/无库存/不存在商品有明确状态。通过后删除该模块原型商品数组。

### 3. 购物车（P1，依赖步骤 2）

实现当前用户购物车增删改查、数量、勾选与失效项；商品列表/详情共用加购动作，结算携带真实条目。`CartItem` 已有模型，仍需 Controller / Service 与页面接入。

**验收**：加购后切页/重启仍保留；数量变更服务端可读；下架、库存不足明确阻止结算，不能仅弹“加购成功”。

### 4. 创建订单与商品订单查询（P1，依赖步骤 3）

后端重新计算金额与库存、保存商品和地址快照、生成订单号；支持幂等提交、待付款订单查询和取消。先按无积分/优惠券抵扣跑通，不能使用结算页写死优惠金额。

**验收**：真实商品/地址提交后订单出现在列表与详情；重复点击不产生重复订单；改前端价格不能改变服务端金额；取消与超时库存处理一致。

### 5. 支付（P1，依赖步骤 4）

支付单、支付调起、结果查询、回调验签与幂等处理、超时关闭、退款。订单是否已支付由后端结果决定。

**验收**：成功、失败、用户取消、重复回调、晚到回调和超时均正确；支付成功后才进入待安装。

### 6. 安装履约及售后（P1，依赖步骤 5）

把现有选日期页接入安装预约接口，包含订单 ID、完整日期、时段、地址；增加派单、安装人员、进度、完工/验收、售后工单。装修施工节点、图片与验收可在此阶段一并规划，但使用各自业务实体。

**验收**：选时后刷新仍能读取；员工看得到自己的任务；服务推进能同步到客户订单；禁止用查询参数直接决定订单状态。

### 7. 积分与优惠券（P2，依赖稳定的订单/支付/退款事件）

先实现真实余额、流水、券列表与有效期，再做发放、锁定、核销、取消返还及退款回退；最后接结算页。删除固定积分和券金额。

**验收**：列表/余额/抵扣一致；同一券不可并发重复使用；取消或退款不会多发、漏退。

### 8. 业绩、反馈与客服（P2）

业绩依赖稳定的归属、签约/完成/取消口径，先定义统计规则再实现汇总、周期筛选、排名和真实项目跳转。反馈实现创建与查询工单、后台处理；客服接入实际服务入口。头像上传响应格式与失败处理同步补齐。

反馈工单相对独立，如近期有运营需求可提前；业绩归属统计应在步骤 1 明确归属规则之后开展。
