# 装修项目取消接口对接说明

后端接口已完成，小程序已开启真实请求。需重启已执行迁移的后端后进行实际环境联调。

## 前端流程

员工项目详情底部的「取消项目」仅在 PENDING_CONFIRM、IN_SERVICE 显示。
点击后填写取消原因（去除首尾空白后 1～500 字符）；服务中项目需要额外勾选「已与客户线下协商一致」。
确认提交成功后关闭弹窗并重新请求详情，不直接修改本地项目状态。
已完成、已取消项目不提供取消操作。客户端只读查看取消记录。

## 接口

PATCH /api/employee/projects/:id/cancel

Authorization: Bearer <token>

```json
{
  "reason": "客户暂缓装修，已电话沟通确认",
  "expectedStatus": "PENDING_CONFIRM"
}
```

- reason：必填字符串，trim 后非空，最长 500 字符。
- expectedStatus：必填，仅 PENDING_CONFIRM / IN_SERVICE，取打开取消弹窗时的项目状态。
- 不提交客户、员工 ID，身份由 JWT 获取。
- 勾选线下协商是前端确认步骤，不作为额外请求字段或法律凭据。

## 后端处理规则

1. 校验有效员工身份，以及项目属于当前员工。
2. 原子更新条件包括项目 ID、负责员工、expectedStatus；不允许将已确认进入服务中的项目按旧的待确认状态取消。
3. 更新 status=CANCELED、cancelReason、canceledAt、canceledByEmployeeId（操作员工 ID 快照），操作者信息由服务端记录。
4. 保留原报价、明细、确认金额及来源预约；不连带删除或取消原预约，不自动新建项目。
5. 不允许重复取消；已完成项目不可取消。
6. expectedStatus 不匹配（如客户并发确认或项目并发完工）返回 409。

成功返回标准项目详情：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 7,
    "status": "CANCELED",
    "cancelReason": "客户暂缓装修，已电话沟通确认",
    "canceledAt": "2026-09-17T08:00:00.000Z"
  }
}
```

data 以上仅展示相关字段，实际返回完整项目详情。员工及客户详情查询同步返回 cancelReason、canceledAt。

## 错误处理

- 400：参数错误，统一请求层提示，保留输入。
- 401：沿用统一登录失效处理。
- 403：员工身份不可用。
- 404：项目不存在或无访问权限。
- 409：状态已变化，提示错误后关闭弹窗、刷新详情；不自动重试取消。
- 网络或其他错误：不修改本地项目，保留输入，恢复提交按钮。

## 联调开关

src/api/project.ts 中 PROJECT_CANCEL_API_ENABLED 当前为 true，确认后发起真实取消请求。
如需临时关闭，可设为 false；此时不会发送取消请求或模拟成功。
列表暂保留现有筛选，已取消记录从「全部」查看；后端应保证 ALL 不排除 CANCELED。
若已存在项目级统计，取消后须同步其统计口径。

## 验收

- 待确认取消、服务中线下协商后取消。
- 空白原因、超长原因、未勾选协商、重复点击。
- 非负责员工访问、已完成或已取消项目操作。
- 客户确认与员工取消并发、完工与取消并发，只有一个状态转换成功。
- 成功后双方详情显示取消记录，不能确认报价、修改报价或再次完成项目。
- 接口关闭时不发请求，不产生本地假取消状态。
